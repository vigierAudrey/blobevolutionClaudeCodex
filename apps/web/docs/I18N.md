# i18n — Traduction multi-langues (next-intl)

## Architecture

- **Bibliothèque** : [next-intl](https://next-intl.dev) v4, branchée via `createNextIntlPlugin('./i18n/request.ts')` dans `next.config.mjs`.
- **Sélection de langue** : cookie `NEXT_LOCALE` (pas de préfixe d'URL). Le composant
  `components/i18n/LanguageSelector.tsx` écrit le cookie puis force un reload complet
  (les Server Components et `<html lang>` sont re-rendus côté serveur).
- **Source de vérité** : `i18n/config.ts` — `LOCALES` (`fr`, `en`, `es`, `de`, `nl`),
  `DEFAULT_LOCALE` (`fr`), `LOCALE_COOKIE`, `resolveLocale()`.
  `i18n/request.ts` résout la locale à chaque requête : cookie absent/invalide → français.
- **Messages** : `messages/<locale>.json`, un fichier par langue, mêmes clés partout.
  Le provider (`NextIntlClientProvider`) est monté dans `app/layout.tsx`.

## État de la migration

| Surface | Statut |
|---|---|
| Home complète (header, hero, cartes, barre jaune, transition, Pourquoi Blob, footer) | ✅ traduite (namespace `home`) |
| Sélecteur de langue | ✅ |
| Funnel auth d'entrée : login, register, AuthForm (2FA, consentement, erreurs serveur), forgot-password, BlobAuthLayout, BackBar, règles mot de passe | ✅ traduit (namespace `auth`, erreurs via `mapAuthErrorToKey`) |
| login-pro, reset-password, verify | ❌ FR en dur (atteints via emails, eux-mêmes FR — cohérent pour l'instant) |
| Dashboard, matching, messages, profil | ❌ FR en dur — namespaces `dashboard`, `matching`… des JSON encore génériques, à réécrire au fil des migrations |
| Metadata / SEO | ❌ volontairement FR (voir Limites) |

### Erreurs serveur

Les messages d'erreur bruts du serveur ne sont **jamais** affichés :
`lib/mapAuthErrorToKey.ts` classe le message en une clé `auth.errors.*`
(fallback `serverGeneric`), affichée via `t()`. `mapAuthErrorToFrench`
subsiste pour les écrans non migrés et lit fr.json (source de vérité unique).

### Tests sans provider

`jest.setup.js` mocke `next-intl` avec un fallback : sans
`NextIntlClientProvider`, `useTranslations` sert les messages **français** —
les tests existants n'ont pas besoin d'être wrappés. Pour tester une autre
langue, monter explicitement le provider (voir `AuthForm.test.tsx`, bloc i18n).

## Migrer une page / un composant

1. **Ajouter les clés** dans `messages/fr.json` (reprendre le texte FR actuel à
   l'identique), puis les 4 autres fichiers. Regrouper par namespace de page
   (`home.header`, `auth.login`…). Les noms propres (spots, marque) ne se traduisent pas.
2. **Composant** (Server ou Client, sync) :
   ```tsx
   import { useTranslations } from 'next-intl';
   const t = useTranslations('home.header');
   <span>{t('login')}</span>
   ```
   Composant serveur `async` : `const t = await getTranslations('…')` (import `next-intl/server`).
3. **Textes composés** : garder les listes de données (`href`, icônes) dans le
   composant et n'y stocker que des **clés** (voir `HomeEditorialCards`, `HomeFooter`).
4. **Tests** : envelopper le rendu dans le provider :
   ```tsx
   import { NextIntlClientProvider } from 'next-intl';
   import fr from '@/messages/fr.json';
   render(<NextIntlClientProvider locale="fr" messages={fr} timeZone="Europe/Paris">…</NextIntlClientProvider>);
   ```

## Garde-fous

- `i18n/__tests__/messages-parity.test.ts` : toute clé présente dans `fr.json` doit
  exister dans les 4 autres langues (et réciproquement), valeurs non vides,
  placeholders ICU identiques. **Une traduction oubliée casse la CI.**
- `i18n/__tests__/config.test.ts` : fallback `resolveLocale` (cookie forgé → `fr`).
- `app/(static)/__tests__/home.page.test.tsx` : la home bascule intégralement en
  anglais avec la locale `en` (aucun résidu FR).
- Jest : `transformIgnorePatterns` autorise la transformation de `next-intl`,
  `use-intl`, `@formatjs/*`, `intl-messageformat` (paquets ESM-only).

## Limites connues (choix assumés)

- **SEO multi-langue impossible avec un cookie** : les crawlers n'envoient pas de
  cookie, ils voient toujours le français. Metadata, sitemap et `hreflang` restent
  donc FR. Si le SEO international devient un objectif, il faudra migrer vers le
  routing par segment `app/[locale]/` de next-intl (chantier séparé, impacte toutes
  les routes).
- `<html translate="no">` reste en place : il bloque l'auto-traduction Chrome qui
  cassait l'hydratation React (commit a72ffc0) ; c'est l'i18n native qui prend le relais.
- Le sélecteur de langue vit dans le widget flottant (engrenage en bas à droite).
